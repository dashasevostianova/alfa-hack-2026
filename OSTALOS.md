# Состояние проекта и отложенные задачи

Обновлено 26 октября 2026 года. Рабочая ветка: `dev-2`.

## Готово

- Общий запуск PostgreSQL, Java, formation, parser и frontend/nginx через корневой Compose.
- Регистрация, вход/выход, cookie-сессия, CSRF; анкеты и заявки сохраняются в PostgreSQL.
- Поиск компании в CSV, ручной ввод для отсутствующего ИНН, подготовка финансов исходными функциями formation.
- Выбор конкретного банковского предложения с названием, ID и ставкой. При подаче Java повторно проверяет предложение и сохраняет его в снимке заявки.
- Исправлено согласованное расхождение с документом: порог на сайте относится к возрасту бизнеса. Возраст вычисляется из даты регистрации; ООО — 9 месяцев, ИП — 3. Срок кредита задаётся отдельно.
- Месячная переплата «Альфа-Селлер Кредита» больше не отображается как годовая ставка. Предложения без сопоставимой годовой ставки показаны для справки, подача по ним блокируется.
- Исторические заявки без названия предложения и единицы ставки сохраняются в БД, но их прежний процент не выдаётся за подтверждённую годовую ставку.
- Анимация формирования, сохранённый отчёт, список заявок и отдельный моковый режим без бэкенда.
- Актуальные README, HTTP-контракт и корневой `struktura.md` с подробной картой всех сервисов.

## Что оставлено на потом

1. **ML — по договорённости с пользователем.** Нужны модель или сервис и контракт входа/выхода. После этого: вызов из Java, сохранение `decision`, обновление статусов и отображение результата. Сейчас новые заявки остаются `SUBMITTED`, искусственных решений нет.
2. **Перенос старых данных — только при необходимости.** Новый Compose использует отдельный том `alpha-credit`; данные старого Compose не переносятся автоматически и не удаляются.
3. **Перед реальным банковским/production-запуском:** согласовать реальные продукты, лимиты и графики платежей; HTTPS, хранение сессий, ограничения частоты запросов, аудит, резервное копирование; при необходимости миграция INTEGER-сумм на BIGINT/NUMERIC. Это отдельный этап, текущий проект — локальный учебный кабинет.

## Практические ограничения

- Сайт банка может менять разметку или временно быть недоступен. При ошибке источник не заменяется выдуманной ставкой; нужно повторить запрос либо проверить парсер.
- Парсер фильтрует форму, возраст бизнеса и залог. Сумма/срок проверяются по учебному Java-каталогу и не вводятся во внешний калькулятор. Аннуитет в кабинете — предварительная оценка; фактические условия кредитной линии/овердрафта отличаются и доступны по ссылке на продукт.
- Для молодого бизнеса без залога источник может показывать только предложения без сопоставимой годовой ставки. Тогда подача через текущий калькулятор недоступна, что является ожидаемым поведением.
- Сессии Java в памяти: перезапуск требует повторного входа. Анкеты и заявки остаются в PostgreSQL.
- Сквозные проверки оставляют синтетические аккаунты и заявки в локальной БД. ИНН из CSV `4217064462` может быть занят тестовым аккаунтом предыдущего этапа; для нового аккаунта используйте другой ИНН. Том с нужными данными не удаляйте.

## Запуск и повторная проверка

Из корня репозитория, после запуска Docker Desktop в режиме Linux containers:

```powershell
docker compose up --build -d --wait
docker compose ps
python scripts/check_integration.py
```

Открыть http://127.0.0.1:8088. Отдельно устанавливать Linux не требуется — Docker Desktop использует WSL 2. Для фронтенда с моками установите `VITE_USE_MOCKS=true` в `frontend/.env.local`, выполните `npm.cmd ci` и `npm.cmd run dev` из `frontend`.

Подробности: [README.md](README.md), [struktura.md](struktura.md), [docs/INTEGRATION.md](docs/INTEGRATION.md).
