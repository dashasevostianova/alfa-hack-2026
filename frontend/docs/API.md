# Контракт Spring Boot

Новый контракт [оформления и демонстрационной выдачи](../../docs/LOAN_FULFILLMENT.md)
описан отдельно. Все новые endpoints реализованы на Spring Boot и используются в основном запуске на `:8088`.

Базовый путь: `/api`. Все тела запросов и ответов — JSON, кодировка UTF-8.

## Сессия и безопасность

Авторизация через серверную cookie-сессию. Пароли не передаются в query string.
Cookie сессии: HttpOnly; Secure в production; SameSite=Lax при одном origin.
Сервер хранит адаптивный хеш пароля, например BCrypt/Argon2, и не возвращает пароль или хеш клиенту.
JSON-ошибки вместо HTML-редиректов Spring Security.

Перед каждым POST фронтенд вызывает `GET /auth/csrf`, затем передаёт возвращённый токен в заголовке с именем `headerName`. Этот endpoint доступен до входа и должен материализовать токен Spring Security в текущей сессии:

```json
{
  "headerName": "X-CSRF-TOKEN",
  "token": "<csrf-token>"
}
```

CSRF применяется также к входу, регистрации и выходу. После входа токен может ротироваться: следующий POST получит новый.

Публичные маршруты: CSRF, login-availability, login, register.
`GET /auth/me` при отсутствии сессии возвращает 401; фронтенд воспринимает это как отсутствие входа.
Все остальные маршруты требуют сессию. При 401 фронтенд возвращает пользователя на вход.

## Эндпойнты

| Метод | Путь после /api | Тело | Ответ |
| --- | --- | --- | --- |
| GET | /auth/csrf | — | 200 `{headerName, token}` |
| GET | /auth/login-availability?login=demo | — | 200 `{available: true}` |
| POST | /auth/register | Credentials | 201 User + сессионная cookie |
| POST | /auth/login | Credentials | 200 User + сессионная cookie |
| GET | /auth/me | — | 200 User либо 401 |
| POST | /auth/logout | — | 204, уничтожение сессии |
| GET | /profile | — | 200 Profile либо JSON `null`, если ещё не заполнен |
| POST | /profile | Profile | 200 сохранённый Profile |
| GET | /loans/products | — | 200 LoanProduct[] |
| POST | /applications | ApplicationDraft | 201 LoanApplication |
| GET | /applications | — | 200 LoanApplication[], новые первыми |

Регистрация в этом контракте сразу создаёт сессию и переводит на анкету.
POST /profile создаёт или обновляет единственную анкету текущего пользователя; после успешного сохранения `User.profileComplete` становится `true`.
POST /applications разрешён только при полной сохранённой анкете. Проверяйте это на сервере.
GET /applications возвращает только заявки текущего пользователя.
Изменение статуса и решения выполняет серверный процесс; клиентского endpoint для подмены решения нет.

## DTO

### Credentials

```json
{
  "login": "demo",
  "password": "DemoPassword1"
}
```

Логин чувствителен к регистру в текущем демо, 3–40 символов `[a-zA-Z0-9_.-]`.
Пароль: минимум 9 символов, хотя бы одна строчная и одна заглавная латинская буква.
Проверка доступности логина предварительная: при регистрации сервер всё равно проверяет уникальность и возвращает 409 при конфликте.

### User

```json
{
  "id": "956c395c-3b64-4828-957d-5a3588a5baab",
  "login": "demo",
  "profileComplete": false
}
```

### Profile

```json
{
  "fullName": "Иван Иванов",
  "email": "demo@example.com",
  "phone": "+79991234567",
  "passport": "1234 567890",
  "companyName": "ООО Демо",
  "inn": "1234567890",
  "industry": "Торговля",
  "monthlyRevenue": 500000
}
```

Состав полей временный. Числовые реквизиты передаются строками, чтобы сохранить ведущие нули.
Текущая фронтенд-проверка ИНН проверяет только длину/цифры; проверка контрольной суммы и внешних реестров — будущая серверная часть.

### LoanProduct

```json
{
  "id": "working-capital",
  "name": "На оборотные средства",
  "description": "Для ежедневных задач бизнеса",
  "annualRate": 22,
  "minAmount": 100000,
  "maxAmount": 10000000,
  "minMonths": 6,
  "maxMonths": 60
}
```

Ставка в процентах годовых, суммы в рублях, срок в целых месяцах.
Сервер может пока возвращать статичный каталог. Демо-продукты описаны в `src/api/mock.ts`.

### ApplicationDraft

```json
{
  "amount": 1000000,
  "months": 24,
  "purpose": "Развитие бизнеса",
  "productId": "working-capital"
}
```

Допустимые цели:

- Пополнение оборотных средств
- Покупка оборудования
- Развитие бизнеса
- Ремонт помещения

Сервер проверяет продукт, лимиты, цель и сохранённость анкеты. Ставку и название продукта берёт из своего каталога и фиксирует в заявке, не доверяя клиенту.

### LoanApplication

```json
{
  "id": "94fae84b-5363-4f29-b259-f7d1ed314950",
  "createdAt": "2026-10-20T12:00:00Z",
  "amount": 3000000,
  "months": 24,
  "purpose": "Развитие бизнеса",
  "productId": "working-capital",
  "productName": "На оборотные средства",
  "annualRate": 22,
  "status": "COMPLETED",
  "decision": {
    "outcome": "REVISION",
    "summary": "Текущая заявка не одобрена. Можно изменить условия и подать новую.",
    "reasons": ["Запрошенная сумма превышает доступный лимит."],
    "recommendations": ["Уменьшите сумму и подайте новую заявку."],
    "suggestedAmount": 2000000
  }
}
```

`status`:

| Код | Название на экране |
| --- | --- |
| SUBMITTED | Отправлено |
| VERIFICATION | Проверка |
| REVIEW | Рассмотрение заявки |
| COMPLETED | Рассмотрено |

До завершения `decision: null`. При `COMPLETED` сервер возвращает заполненное решение.
Поле `createdAt` — ISO 8601 с часовым поясом.

`decision.outcome`:

- `APPROVED`: кнопка «Продолжить» → пока пустая страница.
- `REVISION`: текущая заявка отклонена, возможна новая с другими параметрами; кнопка повторной подачи, сумма берётся из `suggestedAmount`, если она есть.
- `REJECTED`: отказ с подробностями.

`reasons` и `recommendations` — массивы строк, могут быть пустыми.
`suggestedAmount` — необязательное число в пределах продукта. Серверная рекомендация не гарантирует последующее одобрение.

## Ошибки

Единый формат:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "ИНН должен содержать 10 или 12 цифр."
}
```

| Статус | Ситуация |
| --- | --- |
| 400 | Невалидные данные или параметры кредита |
| 401 | Неверный логин/пароль либо сессия отсутствует |
| 403 | Нет разрешения, CSRF невалиден или профиль ещё не заполнен |
| 409 | Логин занят |
| 429 | Лимит запросов |
| 500 | Внутренняя ошибка |

UI показывает `message`, а при отсутствии JSON — стандартный текст с HTTP-кодом.
При неверном входе возвращайте одно сообщение «Неверный логин или пароль», без раскрытия существования аккаунта.
