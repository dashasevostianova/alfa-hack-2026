# Альфа-Бизнес — фронтенд хакатона

React + TypeScript + Vite. Учебный прототип по предоставленному ТЗ и скриншотам; не официальный сервис банка. Точные токены Figma и страница калькулятора оказались недоступны при разработке, поэтому дизайн калькулятора — самостоятельная реализация в стиле приложенных референсов.

## Запуск без бэкенда

Нужен Node.js 22.12+ (либо совместимая более новая версия).
Откройте **Terminal** в PyCharm в корне этого проекта:

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте http://127.0.0.1:5173. Python и запуск `main.py` для фронтенда не нужны.
`npm.cmd` также работает в PowerShell, где выполнение `npm.ps1` запрещено политикой.

Моки включены по умолчанию. Можно явно создать настройки:

```powershell
Copy-Item .env.example .env.local
```

Никакие логины и пароли настоящего банка не используются. Создайте любой тестовый аккаунт:

- Логин: `demo` (если ещё не зарегистрирован).
- Пароль: `DemoPassword1`.
- При регистрации требуется минимум 9 символов, строчные и заглавные латинские буквы.

Затем заполните анкету **вымышленными данными**, например:

| Поле | Значение |
| --- | --- |
| ФИО | Иван Иванов |
| Почта | demo@example.com |
| Телефон | +79991234567 |
| Паспорт | 1234 567890 |
| Компания | ООО Демо |
| ИНН | 1234567890 |
| Сфера | Торговля |
| Месячная выручка | 500000 |

После успешного сохранения доступен подбор кредита.

## Что реализовано

- Отдельные страницы входа и регистрации, проверка логина, пароля и повторного пароля.
- Чёрная навигация и светлая область с закруглениями; адаптация под телефон.
- Личные и бизнес-данные, проверка заполнения, сохранение и загрузка.
- Два демонстрационных продукта, сумма, срок, цель и аннуитетный расчёт.
- Отправка заявки и список заявок текущего пользователя.
- Этапы: отправлено → проверка → рассмотрение → рассмотрено.
- Причины отказа, рекомендации, повторная подача с подставленной суммой.
- Переход после одобрения на пустую страницу внутри кабинета.
- Ошибки запросов, повтор загрузки, блокировка кнопок на время отправки.
- Восстановление сессии, выход, перенаправление при 401 от рабочего API.

## Демонстрационные решения

Статус меняется через 5, 10 и 15 секунд после подачи; список обновляется каждые 3 секунды, пока есть незавершённые заявки.

| Сумма | Результат после 15 секунд |
| --- | --- |
| До 2 000 000 ₽ включительно | Одобрение |
| Более 2 000 000 ₽ и до 5 000 000 ₽ | Отказ с предложением снизить сумму до 2 000 000 ₽ |
| Более 5 000 000 ₽ | Отказ |

Это сценарии интерфейса, **не кредитный скоринг**. В режиме API решение, причины и рекомендации полностью приходят с сервера. Фронтенд не оценивает платёжеспособность.

Демо-база хранится в `localStorage`, активная сессия — в `sessionStorage`. Поэтому обновление страницы сохраняет данные, а закрытие вкладки может потребовать нового входа. Аккаунты разделены по идентификатору пользователя.
Демо-хеш SHA-256 не является защищённой системой аутентификации; для реального режима сервер должен использовать адаптивный хеш пароля. Не вводите реальные персональные данные в демонстрацию.

Для полного сброса выполните в консоли браузера:

```js
localStorage.removeItem('alpha-hackathon-demo-v1');
sessionStorage.removeItem('alpha-hackathon-session-v1');
location.reload();
```

  pages/

    DataPage.tsx

  main.tsx

Поля анкеты временные: сначала измените `Profile` в `src/types.ts`, затем форму в `DataPage.tsx`, валидацию в `lib.ts` и соответствующий серверный DTO.

## Подключение Spring Boot

1. Реализуйте контракт [docs/API.md](docs/API.md).
2. Запустите сервер на `http://localhost:8080`.
3. В `.env.local` установите:

```dotenv
VITE_USE_MOCKS=false
VITE_API_BASE_URL=/api
```

4. Перезапустите Vite. Запросы `/api/*` пойдут через dev-прокси на Spring Boot.

Приложение использует cookie-сессию (`credentials: include`). Dev-прокси позволяет работать без отдельной настройки CORS. Не указывайте Domain=localhost для сессионной cookie при доступе к фронтенду через 127.0.0.1; для локальной разработки используйте cookie без Domain. В production настройте HTTPS, HttpOnly/Secure cookie, CSRF и один origin через reverse proxy.

Вход сделан через **POST**, а не GET из первоначального ТЗ: пароль передаётся в JSON-теле и не попадает в URL. Проверка доступности логина — GET; регистрацию необходимо повторно валидировать на сервере и защитить уникальным ограничением в БД.

Проверки полей в браузере помогают пользователю, но не заменяют серверную валидацию и авторизацию. Сервер получает текущего пользователя из сессии; клиент не отправляет произвольный userId.

## Проверки и production-сборка

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build` проверяет TypeScript и создаёт `dist/`. На production-хостинге настройте SPA fallback: адреса `/data`, `/calculator`, `/applications` должны отдавать `index.html`, а `/api/*` проксироваться в Spring Boot. Dev-прокси Vite не попадает в production-сборку.

Шрифт Manrope загружается из Google Fonts; без интернета используется Arial. Для автономной работы и production можно разместить лицензированный файл шрифта локально.
