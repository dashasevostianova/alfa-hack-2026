# Архитектура приложения

Кредитный кабинет состоит из фронтенда, трех основных серверных сервисов и отдельного сервиса оценки заявки моделью. Сервисы обмениваются данными по HTTP; основной Java API управляет доступом к базе и связывает бизнес-сценарии.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| Фронтенд: React, TypeScript | Страницы входа, анкеты, подбора кредита, заявок и результата. Отправляет запросы через Nginx; не подключается к базе напрямую. |
| Java API: Spring Boot | Основной бэкенд: сессии, профиль, каталог продуктов, проверка банковских предложений и создание заявок. Читает и записывает данные в PostgreSQL. |
| Сервис подготовки данных компании | Проверяет ИНН, находит компанию в предоставленной таблице и рассчитывает финансовые показатели. Не хранит заявки и не подключается к PostgreSQL. |
| Парсер банковских ставок | Получает доступные предложения с сайта банка. Java API повторно проверяет выбранное предложение и ставку перед сохранением заявки. |
| Сервис оценки модели | Принимает признаки заявки и возвращает `0` или `1`, используя существующую модель и scaler. Не пишет в PostgreSQL. |
| PostgreSQL | Основное постоянное хранилище профилей, компаний, продуктов, заявок и финансовых данных. |
| Nginx | Отдает фронтенд и направляет запросы браузера к Java API или сервису модели. |

Итого в текущем запуске — три основных бэкенда и дополнительный сервис оценки модели. Это разделение сохраняет отдельными операции с данными, подготовку сведений компании, поиск ставок и вычисление ML-результата.

## Что хранит база данных

| Таблица | Что хранит и зачем |
| --- | --- |
| `reg` | Учетные записи: логин и хеш пароля. |
| `integration_profile` | Анкету до подачи заявки в JSONB. Нужна, потому что профиль заполняется раньше, чем пользователь выбирает сумму, срок и кредитный продукт. |
| `person` | Персональные и паспортные данные, связанные с учетной записью. |
| `business` | Реквизиты компании: ИНН, форма, дата регистрации и ОКВЭД. ИНН уникален. |
| `product` | Каталог кредитных продуктов и ограничения по сумме и сроку. |
| `application` | Поданные заявки: владелец, продукт, сумма, срок, цель, статус и даты. |
| `finances` | Финансовые показатели заявки. В `account_statements` также хранится снимок подготовленных данных и выбранного банковского предложения, чтобы сохранить условия на момент подачи. |
| `decision` | Таблица для решений по заявкам в общей схеме. Текущий результат ML-модели в нее не записывается. |

Связи между учетной записью, заявкой и финансовыми данными заданы внешними ключами. Удаление учетной записи удаляет связанные с ней данные, а удаление заявки — ее финансовые записи и решения. PostgreSQL проверяет ограничения форматов и допустимых значений на уровне схемы.

Предоставленная таблица компаний — источник для поиска и подготовки показателей, а не отдельная база приложения. Файлы модели также не хранятся в PostgreSQL: сервис оценки загружает их из файлов.

## Как проходит заявка

1. Фронтенд отправляет анкету и параметры кредита в Java API через Nginx.
2. При проверке компании Java API запрашивает сервис подготовки данных. При подборе ставки Java API обращается к парсеру и возвращает предложения фронтенду.
3. При отправке Java API проверяет выбранное предложение и сохраняет заявку вместе с финансовыми данными в PostgreSQL.
4. Страница обработки получает сохраненные параметры заявки и отправляет признаки модели через Nginx в сервис оценки.
5. Ответ модели отображается в истории заявок и сохраняется в `localStorage` браузера, отдельно от базы.

## Почему эта архитектура удобна

- **Ответственность разделена.** Java API управляет заявками и доступом к данным; внешние сервисы выполняют отдельные задачи и могут развиваться независимо.
- **Целостность данных.** База хранит связанные записи с внешними ключами и проверками; Java повторно проверяет ставку перед созданием заявки.
- **Условия заявки сохраняются.** Снимок финансов и предложения фиксирует контекст на момент подачи, даже если профиль или предложения позже изменятся.
- **Фронтенд не имеет прямого доступа к базе.** Nginx проксирует запросы, а доступ к данным контролирует серверное приложение.
- **ML-компонент можно заменить отдельно.** Он имеет простой HTTP-контракт и не связан с Java-схемой базы.
